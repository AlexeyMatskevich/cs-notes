# Динамический массив

**Предпосылки:** [массив](01-array.md) (формула адреса, непрерывность, O(1) доступ по индексу).

Хотим добавлять элементы, не зная заранее сколько их будет. При этом сохранить O(1) доступ по индексу.

## ADT: DynamicCollection

Расширяем IndexedCollection операцией добавления:

| Операция | Сигнатура | Сложность |
|----------|-----------|-----------|
| Получить элемент | `get(i) → value` | O(1) |
| Записать элемент | `set(i, value)` | O(1) |
| Добавить в конец | `append(value)` | O(1) амортизировано |
| Узнать размер | `size() → n` | O(1) |

**Отличие от IndexedCollection:** размер может расти.

## Реализация: Динамический массив (Dynamic Array)

**Этимология:** "Dynamic" — от греческого *dynamis* (сила, способность к изменению). Массив, способный менять свой размер.

**Идея:** храним обычный статический массив внутри, но отслеживаем две величины:
- `capacity` — сколько места выделено
- `length` — сколько элементов реально используется

Пока `length < capacity`, вставка в конец — O(1). Когда `length == capacity` — делаем **resize**.

### Resize: механизм

```
Было:   capacity=4, length=4
        [A][B][C][D]    — массив полон

Хотим добавить E.

Шаг 1: Выделяем новый массив (обычно × 2)
        [_][_][_][_][_][_][_][_]   — capacity=8

Шаг 2: Копируем старые элементы
        [A][B][C][D][_][_][_][_]

Шаг 3: Освобождаем старый массив

Шаг 4: Добавляем новый элемент
        [A][B][C][D][E][_][_][_]   — length=5, capacity=8
```

### Амортизированный анализ

**Амортизация** — из финансов: "растягиваем" большой разовый расход на много маленьких платежей.

После `n` вставок суммарно скопировали: `1 + 2 + 4 + 8 + ... + n/2 ≈ n` элементов.

На `n` операций потратили O(n) работы → в среднем на одну вставку O(1).

### Почему мультипликативный рост

При удвоении после resize есть `n` свободных слотов. Следующий resize через `n` вставок. Баланс расходов и доходов.

При увеличении на 1: каждая вставка вызывает resize. За `n` вставок — O(n²) суммарно.

Главное — **мультипликативный** рост (×2, ×1.5), а не аддитивный (+1, +10).

### Коэффициент роста в реализациях

Коэффициент — деталь реализации: часто это ~1.5× или 2×, но некоторые рантаймы используют формулу «overallocation» или меняют коэффициент в зависимости от размера массива. Смысл один: больший рост реже копирует, но увеличивает пик памяти; меньший рост чаще копирует, но экономит память.

### Накладные расходы памяти

В худшем случае после resize массив заполнен наполовину: до 50% памяти — пустые слоты.

Компромисс: меньший коэффициент — меньше памяти, чаще копируем; больший коэффициент — больше памяти, реже копируем.

### Проблема: O(n) вставка в начало

Доступ по индексу — O(1). Добавление в конец — O(1) амортизированно. Но вставка в начало — по-прежнему O(n): нужно сдвинуть все элементы.

Если задача — часто вставлять в начало или середину, динамический массив неэффективен. [Связный список](03-linked-list.md) решает эту проблему.
