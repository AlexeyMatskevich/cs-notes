# Стек, очередь, дек

**Предпосылки:** [массив](01-array.md), [динамический массив](02-dynamic-array.md), [связный список](03-linked-list.md) (односвязный, двусвязный).

У массива и списка много операций: доступ по индексу, вставка в любое место, удаление из любого места. Иногда это избыточно — и даже вредно.

Если алгоритму нужен только LIFO-порядок (последний пришёл — первый вышел), доступ к середине — источник ошибок, не фича. Ограничение операций даёт:
- **Гарантии корректности** — код не сломает инварианты
- **Свободу реализации** — можно поменять массив на список, не ломая код
- **Документацию намерения** — читающий сразу понимает: "здесь важен LIFO"

## ADT: Stack (Стек)

**LIFO** — Last In, First Out. Последним пришёл — первым вышел.

**Образ:** стопка тарелок. Берёшь верхнюю, которую положил последней.

| Операция | Сигнатура | Сложность |
|----------|-----------|-----------|
| Положить на вершину | `push(x)` | O(1) |
| Снять с вершины | `pop() → x` | O(1) |
| Посмотреть вершину | `peek() → x` | O(1) |
| Проверить пустоту | `empty?() → bool` | O(1) |

**Реализации:**

| Реализация | push | pop | Особенности |
|------------|------|-----|-------------|
| Динамический массив | O(1)* | O(1) | Лучшая локальность |
| Односвязный список | O(1) | O(1) | Нет resize |

На практике почти всегда массив.

**Call stack** работает по LIFO: последняя вызванная функция завершается первой.

### Реализация стека на односвязном списке (Ruby)

```ruby
class Stack
  def initialize
    @head = nil
  end

  def push(value)
    @head = Node.new(value, @head)
  end

  def pop
    return nil unless @head
    value = @head.value
    @head = @head.next
    value
  end

  def peek
    @head&.value  # safe navigation: nil если пусто
  end

  def empty?
    @head.nil?
  end
end
```

**Почему работаем с head, а не tail:** в односвязном списке `pop` с tail требует предыдущий узел — O(n). С head — O(1).

## ADT: Queue (Очередь)

**FIFO** — First In, First Out. Первым пришёл — первым вышел.

**Образ:** очередь в магазине. Кто раньше встал, тот раньше обслужен.

| Операция | Сигнатура | Сложность |
|----------|-----------|-----------|
| Добавить в конец | `enqueue(x)` | O(1) |
| Забрать из начала | `dequeue() → x` | O(1) |
| Посмотреть первый | `front() → x` | O(1) |
| Проверить пустоту | `empty?() → bool` | O(1) |

**Реализации:**

| Реализация | enqueue | dequeue | Особенности |
|------------|---------|---------|-------------|
| Ring buffer | O(1)* | O(1) | Локальность |
| Односвязный список с tail | O(1) | O(1) | Проще код |

`*` — амортизированно, если буфер растёт при переполнении

### Ring Buffer (Кольцевой буфер)

Очередь на наивном массиве неэффективна: `dequeue` оставляет "мёртвую зону" в начале. Кольцевой буфер решает это — два указателя (`head`, `tail`) ходят по кругу.

```
Физически:   [_][_][A][B][C][D][_][_]
                    ↑           ↑
                  head        tail

Переход через край: next = (current + 1) % capacity
```

Обе операции O(1). "Мёртвая зона" становится свободным местом для новых элементов.

## ADT: Deque (Дек)

**Deque** — Double-Ended Queue. Произносится как "deck" (колода карт).

| Операция | Сигнатура | Сложность |
|----------|-----------|-----------|
| Добавить в начало | `push_front(x)` | O(1) |
| Добавить в конец | `push_back(x)` | O(1) |
| Удалить из начала | `pop_front() → x` | O(1) |
| Удалить из конца | `pop_back() → x` | O(1) |

**Почему односвязный список не подходит:** `pop_back` требует предыдущий узел — O(n).

**Реализации:** ring buffer или двусвязный список.

## Сводка: три уровня свободы

| ADT | Добавление | Удаление | Минимальная структура |
|-----|-----------|----------|----------------------|
| Стек | один конец | тот же | массив или односвязный |
| Очередь | один конец | противоположный | ring buffer или односвязный с tail |
| Дек | оба конца | оба конца | ring buffer или двусвязный |

## Проблема: доступ только по числовому ключу

Все три ADT работают с позицией: начало, конец, индекс. Ключ — всегда число.

Что если нужен доступ по произвольному ключу? Строка "alice", объект, UUID? [Хеш-таблица](05-hash-table.md) превращает произвольный ключ в O(1) доступ.
