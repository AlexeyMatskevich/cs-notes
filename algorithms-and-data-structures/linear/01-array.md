# Массив

**Предпосылки:** [абстрактный тип данных](00-adt.md), указатели/ссылки.

ADT Array требует O(1) доступ по индексу при фиксированном размере. Массив как структура данных реализует этот контракт за счёт непрерывного блока памяти и одинакового размера элементов.

## ADT: Array

| Операция | Сигнатура | Сложность |
|----------|-----------|-----------|
| Получить элемент | `get(i) → value` | O(1) |
| Записать элемент | `set(i, value)` | O(1) |
| Узнать размер | `size() → n` | O(1) |

**Инвариант:** допустимые индексы от 0 до n-1. Размер фиксирован при создании.

## Реализация: Массив (Array)

**Этимология:** "Array" (англ.) — буквально "ряд", "строй", "расстановка". Военный термин: солдаты выстроены в ряд, плечом к плечу, без промежутков.

**Определение:** структура данных, которая хранит фиксированное количество элементов одного типа в непрерывном блоке памяти. Одинаковый размер элементов и отсутствие дыр между ними — вот что делает возможным O(1) доступ по индексу.

### Почему O(1) — вывод, а не магия

Пусть массив начинается с адреса `base`, каждый элемент занимает `size` байт. Тогда элемент с индексом `i` лежит по адресу:

```
address(i) = base + i × size
```

Одно умножение, одно сложение — количество операций не зависит от `n`. Отсюда O(1).

**Важно:** формула работает только потому, что все элементы одного размера. Если элементы разного размера, формула ломается.

### Представление в памяти

```
┌─────────────────────────────────────────────────────┐
│  base                                               │
│   ↓                                                 │
│  [elem 0][elem 1][elem 2][elem 3]...[elem n-1]      │
│   ←size→ ←size→  ←size→                             │
└─────────────────────────────────────────────────────┘
```

Три параметра определяют массив:
- `base` — адрес начала
- `size` — размер одного элемента в байтах
- `n` (или `length`) — количество элементов

### Инварианты массива

1. **Непрерывность:** элементы занимают адреса от `base` до `base + n × size - 1` без пропусков
2. **Однородность:** каждый элемент занимает ровно `size` байт
3. **Границы:** допустимые индексы — от `0` до `n-1` включительно

Нарушение инварианта 3 — **выход за границы массива**. В C это неопределённое поведение. В языках с проверкой границ (Rust/Java/Python) это паника или исключение. В Ruby поведение зависит от операции: `arr[i]` обычно возвращает `nil`, а `arr.fetch(i)` поднимает `IndexError`.

### Операции и сложность

| Операция | Время | Почему |
|----------|-------|--------|
| Чтение по индексу | O(1) | Формула адреса |
| Запись по индексу | O(1) | Формула адреса |
| Поиск по значению | O(n) | Нужно проверить каждый элемент |
| Вставка в позицию i | O(n) | Сдвиг элементов |
| Удаление из позиции i | O(n) | Сдвиг элементов |

Сдвиг — цена за непрерывность: чтобы сохранить порядок, элементы после места операции приходится перемещать.

### Что если элементы разного размера?

Два решения:

**1. Padding (выравнивание)** — добавляем пустые байты, чтобы все элементы занимали одинаковое место. Так работают структуры в C. Платим памятью.

**2. Массив указателей** — сам массив хранит указатели одинакового размера, а данные лежат отдельно в куче. Так устроены массивы в Ruby, Python, Java. Формула работает для указателей, но теряем **локальность данных**.

Указатель — адрес в памяти, не обязательно в куче: он может указывать на стек, статическую память, куда угодно. "Куча" здесь — типичный случай для динамически создаваемых объектов.

### Локальность данных

Процессор читает память **кэш-линиями** — блоками фиксированного размера (часто 64 байта; зависит от CPU). Когда читаешь один байт, обычно загружается вся линия вокруг него.

В "честном" массиве (элементы подряд) обход — последовательное чтение. Кэш работает идеально.

В массиве указателей каждый указатель ведёт в «случайное» место памяти. Каждый прыжок — потенциальный **cache miss**. Попадание в L1 обычно стоит единицы циклов, промах до RAM — сотни циклов. Поэтому «прыжки по указателям» часто доминируют над асимптотикой.

### Проблема: фиксированный размер

Массив реализует ADT Array, но размер фиксирован при создании. Если заранее неизвестно сколько элементов будет — массив неудобен. Выделять "с запасом" — тратить память. Выделять "впритык" — не влезет новый элемент. [Динамический массив](02-dynamic-array.md) решает эту проблему.
