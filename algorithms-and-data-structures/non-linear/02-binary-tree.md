# Бинарное дерево

**Предпосылки:** [дерево](01-tree.md) (корень, родитель, ребёнок, лист, глубина, высота), [стек и очередь](../linear/04-stack-queue-deque.md) (LIFO/FIFO — используются для обходов).

Ограничение до двух детей на узел даёт фиксированные имена — **левый** и **правый** — и позволяет принимать решение "влево или вправо" за O(1), что лежит в основе эффективного поиска. Такое дерево называется **бинарным** (от латинского *binarius* — "состоящий из двух"):

```ruby
class Node
  attr_accessor :value, :left, :right

  def initialize(value)
    @value = value
    @left = nil
    @right = nil
  end
end
```

## Обходы деревьев

Деревья хранят данные, но чтобы эти данные использовать, нужно их обойти — посетить каждый узел. Для деревьев хватает стека/очереди; для графов к этому почти всегда добавляется `visited`, чтобы не зациклиться на циклах.

### Поиск в глубину (Depth-First Search, DFS)

*Depth* — глубина. Идём вглубь, пока можем, потом возвращаемся. Использует стек (или рекурсию — call stack).

Для бинарного дерева есть три варианта порядка:

```text
       1
      / \
     2   3
    / \
   4   5
```

| Обход | Порядок для узла | Результат |
|-------|------------------|-----------|
| Pre-order | узел → левое → правое | 1, 2, 4, 5, 3 |
| In-order | левое → узел → правое | 4, 2, 5, 1, 3 |
| Post-order | левое → правое → узел | 4, 5, 2, 3, 1 |

Pre-order используют для сериализации дерева: если записать узлы в порядке "корень, левое, правое", то при чтении первый элемент — всегда корень, и дерево восстанавливается рекурсивно. In-order для дерева поиска даёт элементы в отсортированном порядке, потому что обходит "меньшие → текущий → большие". Post-order обрабатывает детей до родителя, что нужно для удаления дерева (нельзя удалить узел, пока не удалены его дети) или вычисления размера поддеревьев (размер узла = 1 + размер левого + размер правого).

### Поиск в ширину (Breadth-First Search, BFS)

*Breadth* — ширина. Обрабатываем все узлы на текущем уровне, прежде чем спускаться глубже. Использует очередь (FIFO). Для того же дерева результат: 1, 2, 3, 4, 5 (по уровням).

### Когда что использовать

| Критерий | DFS | BFS |
|----------|-----|-----|
| Структура данных | Стек | Очередь |
| Стратегия | Вглубь до упора | По уровням |
| Память | O(h), h — высота | O(w), w — макс. ширина |

BFS находит ближайший (неглубокий) элемент, DFS удобен для поиска глубоко спрятанного элемента или когда дерево широкое, но неглубокое.

## Формы бинарного дерева

Обходы работают на любом бинарном дереве, но эффективность операций зависит от формы — насколько дерево заполнено и сбалансировано.

**Полное (full) бинарное дерево** — каждый узел имеет либо 0, либо 2 детей (нет узлов с одним ребёнком).

**Завершённое (complete) бинарное дерево** — все уровни заполнены, кроме, возможно, последнего, который заполняется строго слева направо. Завершённое дерево из n узлов имеет высоту ⌊log₂(n)⌋, и его можно компактно хранить в массиве без указателей — это свойство использует [куча](04-heap.md).

**Совершенное (perfect) бинарное дерево** — все уровни полностью заполнены. Содержит ровно 2ʰ⁺¹ − 1 узлов при высоте h.

Обход позволяет посетить все узлы, но линейный поиск по всем узлам занимает O(n). Если элементы упорядочены, можно искать за O(log n). [Двоичное дерево поиска](03-binary-search-tree.md) использует инвариант порядка для этого.
