# Граф

**Предпосылки:** базовые понятия программирования, [массив](../linear/01-array.md), [хеш-таблица](../linear/05-hash-table.md).

Все рассмотренные ранее структуры хранят элементы в последовательности — по позиции или по ключу. Но когда в данных есть **сущности и связи** (города и дороги, задачи и зависимости, пользователи и подписки), плоская последовательность не выражает эти отношения. Граф — обобщение, где любая вершина может быть связана с любой другой.

## Определение

Граф — абстракция отношений: **вершины** (vertices) — это объекты, **рёбра** (edges) — связи между ними. Модель удобна, когда важно "кто с кем связан", а не только сами значения.

Формально граф записывают как `G = (V, E)`: множество **вершин** (V) и множество **рёбер** (E), где каждое ребро соединяет две вершины. Вершины — это "что-то" (города, люди, файлы), рёбра — "связь существует".

### Виды графов

В **неориентированном графе** ребро — множество из двух вершин {u, v}. Порядок не важен, связь симметричная: дружба в соцсети (если А дружит с Б, то Б дружит с А).

В **ориентированном графе** (directed graph, digraph) ребро — упорядоченная пара (u, v). Направление важно: (u, v) ≠ (v, u). Такие рёбра называют дугами (arcs). Пример: подписки в Twitter — я подписан на тебя, но ты на меня нет.

Во **взвешенном графе** (weighted graph) каждому ребру сопоставлено число (вес): расстояния между городами, стоимость авиабилетов.

Взвешенность и ориентированность — независимые свойства. Граф может быть неориентированным невзвешенным (дружба), неориентированным взвешенным (дороги с расстояниями), ориентированным невзвешенным (подписки) или ориентированным взвешенным (авиарейсы с ценами).

## Путь и Цикл

Частая операция на графе — понять достижимость: можно ли добраться из одной вершины в другую.

**Путь** — это последовательность вершин (v₀, v₁, v₂, ..., vₖ), где каждая соседняя пара соединена ребром. В ориентированном графе путь должен следовать направлению рёбер. В невзвешенном графе длина пути — количество рёбер, во взвешенном — сумма весов.

**Цикл** — путь, который начинается и заканчивается в одной вершине, а все остальные вершины в нём не повторяются. Графы без циклов называются **ациклическими**.

Для неориентированного графа граф называется **связным**, если между любыми двумя вершинами существует путь. Несвязный граф распадается на отдельные компоненты, между которыми нет путей.

Для ориентированного графа связность уточняют: граф **сильно связен**, если для любых двух вершин `u` и `v` существует путь из `u` в `v` и обратно. **Слабо связен** — если при игнорировании направлений рёбер граф становится связным. Это различие важно на практике: например, в графе веб-страниц (страница → ссылка) из страницы A может быть путь к B, но не наоборот.

## Хранение графа в памяти

Граф описывает связи, но чтобы программа могла с ним работать, нужно представить его в памяти. Выбор представления почти всегда упирается в компромисс: быстро проверять наличие ребра или быстро перечислять соседей. Есть два основных способа.

### Матрица смежности (Adjacency Matrix)

Таблица V×V, где в ячейке [i][j] храним информацию о ребре между вершинами i и j.

```text
        Петя  Маша  Катя
Петя  [  0     1     0  ]
Маша  [  1     0     1  ]
Катя  [  0     1     0  ]
```

Для неориентированного графа матрица симметрична относительно главной диагонали ([i][j] = [j][i]), а диагональ заполнена нулями (если нет петель).

Память: O(V²). Проверить ребро между i и j — O(1), найти всех соседей вершины — O(V) (нужно пройти всю строку). Добавление новой вершины требует создать матрицу (V+1)×(V+1) и скопировать старые данные — O(V²). Матрица удобна для плотных графов (много рёбер) и когда часто нужно проверять наличие ребра.

### Списки смежности (Adjacency Lists)

Для каждой вершины храним список её соседей:

```ruby
{
  Петя: [Маша],
  Маша: [Петя, Катя],
  Катя: [Маша]
}
```

Память: O(V + E). **Степень вершины** (degree) — количество рёбер, инцидентных вершине; в списке смежности это длина списка соседей. Найти всех соседей — O(degree), проверить наличие конкретного ребра — тоже O(degree), потому что нужно пройти по списку. Списки удобны для разреженных графов (мало рёбер) и когда часто нужно обходить соседей.

### Сравнение

| Критерий | Матрица смежности | Списки смежности |
|----------|-------------------|------------------|
| Память | O(V²) | O(V + E) |
| Проверить ребро | O(1) | O(degree) |
| Найти соседей | O(V) | O(degree) |
| Добавить ребро | O(1) | O(1) |
| Удалить ребро | O(1) | O(degree) |
| Добавить вершину | O(V²) | O(1) |

Граф — общая структура, но для многих задач нужна более строгая форма. Если из связного графа убрать все "лишние" рёбра так, чтобы между любыми двумя вершинами остался ровно один путь — получится [дерево](01-tree.md).
