# /note:research — исследование + видение автора

Ты начинаешь процесс создания нового учебного материала. Эта фаза — исследование: что есть в репозитории, чего не хватает, куда встроится новый материал. И — совместный brainstorm с автором.

## Входные данные

Тема от пользователя: `$ARGUMENTS`

## Шаг 1: Исследование репозитория

Запусти Explore subagent для исследования. Он должен:

1. Прочитать `index.md` в целевом домене и соседних доменах
2. Найти все упоминания темы в репозитории (`Grep`)
3. Проследить цепочки `Предпосылки` от возможных зависимостей
4. Прочитать 2-3 образцовые заметки из того же домена (чтобы увидеть паттерны)
5. Определить: какие заметки уже покрывают смежные темы, где пробелы

Важно: существующие заметки могут не соответствовать styleguide — отмечай, какие паттерны хорошие, а какие нет (для этого прочитай первые 2-3 абзаца каждой найденной заметки).

## Шаг 2: Совместный brainstorm

Представь пользователю находки из репозитория. Затем начни совместный brainstorm.

**Ты — не секретарь, а партнёр по мышлению.** Автор может ошибаться, знать тему отдалённо или не до конца. Твоя задача:

- **Собирай видение:** «Как вы это видите? Какая ключевая идея?»
- **Проверяй факты:** если автор утверждает X, но ты знаешь что X неточно — говори
- **Предлагай альтернативы:** «А что если подать через Y?», «Может, начать с Z?»
- **Push back:** «Это фреймирование может запутать новичка, потому что...»
- **Помогай думать:** «Вот что я знаю об этой теме — вот где сложности»

Используй AskUserQuestion для структурированных вопросов:

1. «Какая ключевая идея/инсайт, который вы хотите донести?»
2. «В чём главная сложность объяснения этой темы?»
3. «Какая самая частая ошибка в понимании?»
4. «На каком уровне глубины останавливаемся?»

## Шаг 3: Запись результатов

Запиши результат в `wip/<slug>-research.md` со следующей структурой:

```markdown
---
phase: research
status: draft
topic: <название темы>
files: []
---

# Research: <тема>

## Состояние репозитория
- Существующие заметки по смежным темам (с оценкой качества)
- Пробелы, которые заполнит новый материал

## Зависимости
- Кандидаты в предпосылки (конкретные файлы с путями)
- Файлы, которые потребуют каскадных обновлений (с описанием что именно менять)

## Характеристики
- Слой знания: фундамент / механизм / технология / прикладной
- Целевой читатель и его уровень
- Scope и что НЕ в scope
- Паттерны из домена (какие хорошие, какие нет)

## Видение автора
- Ключевая идея / инсайт
- Главная сложность объяснения
- Частые ошибки в понимании
- Целевая глубина
- Примеры/аналогии, предложенные автором
- Языки/инструменты для примеров (если обсуждались)

## Предложенная структура
(сырые идеи из brainstorm для фазы design)
- Примерный список файлов с аннотациями
- Идеи по нарративной дуге (проблема→решение цепочка)
- Фазы / группировки если есть

## Нарративная дуга
(если в brainstorm сложилась цепочка — записать)

## Границы с существующим контентом
| Тема | Здесь | Другой домен |
|------|-------|--------------|

## Кросс-ссылки (планируемые)
- Из новых файлов наружу
- Из существующих файлов внутрь

## Зоны риска
(темы где сложно, автор не уверен, новичок может запутаться — с митигацией)
```

Секции ниже «Видение автора» — опциональные. Включай если brainstorm их затронул, не заполняй пустышками. Главное: **всё что обсуждалось в brainstorm должно быть записано** — если в диалоге появилась информация, которая не ложится ни в одну секцию, добавь подходящую секцию.

Покажи пользователю краткое резюме и предложи перейти к следующей фазе: `/note-design <slug>`.
