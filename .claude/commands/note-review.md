# /note:review — проверка тремя ревьюерами

Запусти 3 параллельных subagent для верификации черновика.

## Входные данные

Slug: `$ARGUMENTS`
Прочитай:
- `wip/<slug>-design.md` — дизайн + структура + план интеграции
- `wip/<slug>-design.md` — дизайн (для контекста)
- Определи пути файлов из `files[]` в design.md frontmatter

## Запуск 3 ревьюеров ПАРАЛЛЕЛЬНО

Запусти все три Agent subagent в одном сообщении:

### Subagent A: Структурный ревьюер + интеграция

Промпт для агента:

```
Ты — структурный ревьюер. Проверь заметку по structure-guide.md и плану интеграции.

Прочитай:
- structure-guide.md (§2-8, §11)
- wip/<slug>-design.md (секция Integration plan)
- Сами файлы заметок: [пути]

Проверь:
1. Именование и нумерация (kebab-case, NN-префикс)
2. Блок Предпосылки присутствует и корректен
3. prev/next навигация корректна
4. Cross-links в месте первого упоминания
5. index.md обновлён
6. Sources есть если нетривиальные утверждения
7. ИНТЕГРАЦИЯ: каждый пункт из Integration plan реально выполнен
8. Двунаправленность ссылок: если заметка ссылается на X, X ссылается обратно
9. Не сломана логика существующих заметок после интеграции

Формат ответа: pass/fail на каждый пункт с однострочным обоснованием.
```

### Subagent B: Чеклист-ревьюер

Промпт для агента:

```
Ты — чеклист-ревьюер. Проверь заметку по всем 7 мини-чеклистам из styleguide.md.

Прочитай:
- styleguide.md (все мини-чеклисты: §1, §3, §4, §5, §6, §7, §8)
- Файлы заметок: [пути]
- Файлы предпосылок: [пути]

Проверь все 33 пункта:

§1 — Предпосылки и зависимости (6 пунктов):
- Блок Предпосылки полный?
- Каждый термин объяснён или в Предпосылках?
- Нет декоративно точных терминов?
- Непрозрачные имена получили опору?
- Кодовые имена привязаны (что+где+зачем)?
- Омонимы разведены?

§3 — Вход в тему (6 пунктов):
- Живой вопрос в начале?
- Мотивация локальна?
- Роль→термин?
- Max 1-2 новых сущности в первом абзаце?
- Тип сценария выбран?
- Для последовательной: показано где предыдущее решение не работает?

§4 — Нить и связность (5 пунктов):
- Нить выбрана, факты привязаны?
- Мостики где переход неочевиден?
- Нет решений без симптома?
- Детали по сценарию?
- Нет самореференции?

§5 — Постепенность (4 пункта):
- Назначение до устройства?
- Абстрактный слой для 3+ компонентов?
- Нет прыжков через масштаб?
- Глубина по роли?

§6 — Эффект (4 пункта):
- Ясно какой вопрос заметка закрывает?
- Эффект в системе = наблюдаемое?
- Ясно когда применять?
- Причина/следствие не перепутаны?

§7 — Точность и стиль (4 пункта):
- После «что это» есть «как работает»?
- Жизненный цикл покрыт?
- Код минимален + «почему» в прозе?
- Формат по сканируемости?

§8 — Слои (4 пункта):
- Не объясняет концепцию чужого слоя?
- Предпосылки смотрят вниз?
- Ссылки вверх не создают скрытых баз?
- Каскадные изменения проверены?

Формат ответа: pass/fail/concern на каждый пункт с однострочным обоснованием.
```

### Subagent C: Наивный читатель (КЛЮЧЕВОЙ)

Промпт для агента:

```
Ты — ученик, который знает РОВНО следующее и НИЧЕГО больше:
- Нетехнический baseline: связный текст, простая причинность, школьная арифметика, тривиальная нотация
- Содержание этих конкретных файлов-предпосылок:
  [для каждого файла-предпосылки прочитай его и дай резюме в 2-3 предложениях]

Ты НЕ знаешь:
- Ничего технического, чего нет выше
- Ни одного термина, не определённого выше
- Ни одной концепции, которая «кажется очевидной» программисту

Твоя задача читать материал так словно ты учишься по материалу, чтобы на основе твоего опыта обучения понять удачный ли материал или с ним есть проблемы

Прочитай заметку: [путь]

== МЕТОД: ПОСТРОЕНИЕ МЕНТАЛЬНОЙ МОДЕЛИ ==

Читай по 5 строк за раз. ЕСЛИ ТЫ ЧИТАЕШЬ БОЛЬШЕ 5 СТРОК ЗА РАЗ ТО ЗАДАЧА ПРОВАЛИЛАСЬ ПОЛНОСТЬЮ. После каждого блока:

1. **Моя ментальная модель ДО блока:**
   Набор утверждений «я понимаю, что...» простыми предложениями.
   Начальная модель = только предпосылки.

2. **Что этот блок делает с моей моделью:**
   - РАСШИРЯЕТ: новое «я теперь понимаю, что...»
   - СВЯЗЫВАЕТ: как A связано с B
   - УГЛУБЛЯЕТ: деталь к уже понятному
   - НЕ МЕНЯЕТ: шум?

3. **Проблемы** (если есть):
   - MODEL_BREAK: противоречит уже построенному
   - HIDDEN_KNOWLEDGE: нужно знание вне предпосылок и прочитанного
   - DANGLING: открыт вопрос, не закрыт (отслеживай!)
   - NO_CONNECTION: слова понятны, но как это связано с моделью — нет
   - OVERLOAD: слишком много нового, модель не успевает
   - MOTIVATION_GAP: объясняют КАК, но я не понимаю ЗАЧЕМ

4. **Вердикт блока:** CLEAR / CONCERN / BLOCKER

== ПРОВЕРКА ЗАКРЫТИЯ МОДЕЛИ ==

После последнего блока:
- Есть ли НЕЗАКРЫТЫЕ вопросы?
- Закрылся ли вопрос из начала (мотивация)?
- Могу ли объяснить тему кому-то, используя ТОЛЬКО финальную модель?
- Есть ли «висящие» утверждения — ни к чему не привязаны?

Будь adversarial. Главный враг автора — проклятие знания.

В конце: финальная модель + общий вердикт + сводка BLOCKER/CONCERN с номерами строк.
```

## Сборка отчёта

После получения результатов от всех трёх агентов, запиши в `wip/<slug>-review.md`:

```markdown
---
phase: review
status: draft
topic: <тема>
---

# Review: <тема>

## Структурный ревьюер (Subagent A)
[результаты]

## Чеклист-ревьюер (Subagent B)
[результаты]

## Наивный читатель (Subagent C)
[результаты]

## Сводка
- BLOCKER: N
- CONCERN: M
- Критичные строки: [список]
```

## Чекпоинт

Покажи сводку и используй AskUserQuestion:

«Ревьюеры нашли N проблем (X critical, Y concern). Как поступить?»
- «Исправить все» → исправь + перезапуск всех 3 ревьюеров
- «Исправить критичные» → только BLOCKER + fail → перезапуск naive reader
- «Проверю вручную»
- «Принять как есть»

Цикл повторяется пока нет BLOCKER у naive reader И нет fail у checklist, или пользователь принимает вручную.
