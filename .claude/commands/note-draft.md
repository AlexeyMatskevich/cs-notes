## Написание

Для каждого файла из design.md работай **по звеньям дуги**, не монолитно.

### Стиль прозы

Текст пишет не документацию, а объяснение для человека. После каждого абзаца — один тест: **«если бы я объяснял это коллеге устно, я бы сказал именно так?»** Если нет — переписать так, как сказал бы.

Устное объяснение начинается с ситуации, которую собеседник узнаёт, а не с технического артефакта. Оно не пакует шесть деталей в одно предложение. Оно даёт модель, а потом оговорки — не наоборот. Конкретная форма каждый раз разная и зависит от мысли, которую передаёшь.

### Цикл на каждое звено дуги

Для каждого звена/секции:

**1. Что читатель понимает прямо сейчас?**
Сформулируй: какие утверждения читатель может сделать после предыдущей секции? Это стартовая точка. Для первой секции = только предпосылки.

**2. Какие утверждения ты собираешься сделать?**
Перечисли конкретные технические claims этой секции. Для каждого: уверен ли ты? Если нет — верифицируй через context7 (для конкретных технологий) или WebSearch (механизмы, числа, edge cases). Ищи ответы на конкретные вопросы, не «всё про тему».

Для серий: запусти агента (name: "researcher", run_in_background) для исследования следующего звена, пока пишешь текущее.

**3. Напиши секцию.**
Читатель пришёл из состояния (п.1) и должен прийти к пониманию, которое создаёт потребность в следующем звене. Как подать — решай заново для каждой секции исходя из конкретной мысли и состояния читателя (§4.5, §7.2). Точка входа из design.md для первой секции (порядок «роль→имя» сохрани).

**Инварианты** (проверяй механически после написания секции):
- Термин: объяснён выше или в Предпосылках (§1.2)
- Непрозрачное имя: смысловая опора при первом вводе (§1.3)
- Кодовое имя: что + где + зачем (§1.3)
- Метаязык и самореференция отсутствуют (§0.1)
- Текст в пределах пола/потолка документа
- Переход к следующей секции: причинная связь очевидна? Если нет — мостик (§4.2)
- **Тест вслух** — если бы объяснял это коллеге, сказал бы именно так?

### Проверка файла читателем

После каждого файла (все звенья написаны) запусти агента (name: "reader", run_in_background для серий — пока reader проверяет файл N, готовь файл N+1):

```
Ты знаешь РОВНО следующее:
- Baseline: связный текст, простая причинность, школьная арифметика
- Концепции из предпосылок:
  [прочитай каждый файл-предпосылку и извлеки список: какие концепции, термины и механизмы читатель из него усвоил]
- [если файл не первый] Концепции из предыдущих файлов серии:
  [аналогично — прочитай и извлеки список усвоенных концепций]

Прочитай проверяемый файл: [путь]

Читай по 5 строк. После каждого блока:
1. Моя модель ДО: «я понимаю, что...»
2. Что блок сделал: РАСШИРЯЕТ / СВЯЗЫВАЕТ / УГЛУБЛЯЕТ / НЕ МЕНЯЕТ
3. Проблемы: HIDDEN_KNOWLEDGE / MODEL_BREAK / DANGLING / NO_CONNECTION / OVERLOAD / MOTIVATION_GAP
4. Вердикт: CLEAR / CONCERN / BLOCKER

После последнего блока: незакрытые вопросы? Закрылась мотивация? Могу объяснить тему?
Ответь КРАТКО: BLOCKER и CONCERN с номерами строк + финальная модель.
```

BLOCKER или HIDDEN_KNOWLEDGE или MODEL_BREAK → исправь, перезапусти. CONCERN → исправь по усмотрению.

### Стыковка (для серий)

Конец файла N → мотивация файла N+1?

## Вычитка серии (для мультифайловых серий)

После всех файлов собери в параллельные списки:
1. Все мосты (последний абзац каждого файла)
2. Все определения («X — это Y»)
3. Все открывающие абзацы

Если в любом списке одна конструкция повторяется 2+ раза подряд — перепиши повторы. Варианты подачи: вопрос, контраст, пример, роль, одно предложение, убрать.
