# Research: foundations/ — биты, байты, представление данных

## Состояние репозитория

### Масштаб пробела

~203 файла в репозитории используют понятия бит/байт/двоичная система. Систематического фундаментального объяснения нет — существуют только **контекстные микро-определения**, встроенные в чужие темы:

- `networking/foundations/00-ethernet-and-switching.md` (строки 7–11): определяет бит, байт, 2⁸ = 256 — как ступеньку к кадрам и коммутации
- `computer/data-path/00-memory-hierarchy.md` (строка 279): объясняет hex → бит маппинг — как инструмент для разбора кеш-адреса

Эти микро-объяснения не покрывают «почему» (почему двоичная, почему 8 бит), не дают систематики (целые числа, two's complement, побитовые операции, float, кодировки), и не могут служить единой точкой ссылки для остальных доменов. Foundations/ не дублирует, а **консолидирует**: после его появления Ethernet-заметка сможет ссылаться на foundations/ вместо собственного мини-объяснения.

## Характеристики

- **Слой знания:** фундамент (ниже всех существующих доменов)
- **Целевой читатель:** любой, кто хочет понять как компьютер представляет данные. Знание: школьная математика. Не требует программирования.
- **Scope:** двоичная система, целые числа, побитовые операции, IEEE 754, текстовые кодировки, endianness
- **НЕ в scope:** конкретные языки программирования, архитектура процессора (это computer/), сетевые протоколы (это networking/)
- **Паттерны из домена:** домен новый, но наследует лучшие паттерны из programming/ и computer/

## Видение автора

- **Ключевая идея:** «Почему именно так» — фокус на инженерных и исторических причинах каждого решения (почему двоичная, почему 8 бит, почему two's complement, почему IEEE 754)
- **Главная сложность объяснения:** материал кажется «школьным» и скучным, нужно показать что каждое решение — это инженерный компромисс с альтернативами
- **Целевая глубина:** полная (IEEE 754 с denormals/NaN/Infinity; Unicode с grapheme clusters и нормализацией; endianness — полный файл)
- **Примеры:** псевдокод, таблицы, ASCII-диаграммы, пошаговые расчёты. Без привязки к языку программирования
- **Читатель:** самостоятельный, не зависит от programming/. Предпосылки: школьная математика

### Частые ошибки в понимании (для учёта при дизайне)

1. **Two's complement как магия** — запоминают «инвертируй + 1», не понимают зачем (единая схема сложения для signed/unsigned)
2. **Float «почти точный»** — 0.1+0.2 ≠ 0.3 воспринимается как баг, а не как следствие конечной двоичной дроби
3. **UTF-8 = Unicode** — путают каталог символов и способ записи в байты
4. **«Байт = 8 бит очевидно»** — были 6-, 7-, 9-битные байты; 8 — историческое решение IBM System/360
5. **«Одни биты — разные вещи»** — главный инсайт: `01000001` = число 65 = буква 'A' = часть float; всё зависит от интерпретации

### Аннотации

- **00-binary-and-bytes:** Почему двоичная (транзистор — два состояния) → бит → группировка в байты (почему 8? IBM System/360) → степени двойки (КБ/МБ/ГБ) → hex как удобная запись. Центральный инсайт: одни и те же биты — разные вещи в зависимости от интерпретации.
- **01-integers:** Натуральное продолжение: как из битов получить числа. Unsigned → signed (знаковый бит? плохо: два нуля, сложение ломается) → two's complement (почему работает: модулярная арифметика, единая схема сложения). Overflow и wrap-around.
- **02-bitwise-operations:** Инструменты для работы с отдельными битами. AND/OR/XOR/NOT/shift. Практика: маски (выделить бит, установить, сбросить), флаги, права доступа (chmod).
- **03-floating-point:** Проблема: целых мало, нужны дроби. Фиксированная точка → зачем плавающая (диапазон vs точность). IEEE 754: знак + экспонента + мантисса. Нормализация, денормализованные, NaN, ±Infinity, ±0. Почему 0.1 + 0.2 ≠ 0.3.
- **04-text-encoding:** Как биты становятся буквами. Телеграф → ASCII (7 бит, 128 символов, хватает для английского). Проблема: мир не только английский → кодовые страницы (хаос) → Unicode (единый каталог, code points, planes). Способы записи: UTF-32 (просто, расточительно) → UTF-16 (компромисс, суррогатные пары) → UTF-8 (переменная длина, обратно совместим с ASCII). BOM, нормализация, grapheme clusters.
- **05-endianness:** Число больше байта → в каком порядке хранить байты? Little-endian (младший первый, x86), big-endian (старший первый, сетевые протоколы). Почему x86 выбрал little-endian. Где стреляет: файлы, сеть, сериализация. htonl/ntohl.

## Нарративная дуга

Сквозная проблемная цепочка:

```
Транзистор имеет два состояния
  → бит (минимум информации)
    → одного бита мало → группируем → байт (почему 8?)
      → из байтов нужно составить числа → unsigned → signed → two's complement
        → числа нужно комбинировать на уровне битов → побитовые операции
          → целых мало, нужны дроби → IEEE 754
            → нужны не только числа, но и текст → кодировки
              → числа больше байта нужно хранить/передавать → порядок байтов
```

Каждый файл заканчивается проблемой, которую решает следующий.

## Зоны риска

1. **Скука «школьного» материала.** Митигация: каждое решение подаётся как инженерный компромисс с альтернативами. «Почему не десятичная?» «Почему не знаковый бит?» «Почему не фиксированная точка?»
2. **IEEE 754 — когнитивная перегрузка.** Митигация: послойное раскрытие. Сначала идея (знак + масштаб + точность), потом конкретная раскладка бит, потом edge cases (denormals, NaN). `<details>` для доказательств.
3. **Unicode — объём.** Полная тема (с grapheme clusters, нормализацией) может раздуть файл. Митигация: core path (ASCII → проблема → Unicode → UTF-8) плюс advanced sections в `<details>`.
4. **Endianness — пересечение с ABI.** Митигация: foundations/ объясняет концепцию, ABI-заметка ссылается. Нужно аккуратно вырезать секцию из ABI без потери связности.
5. **Псевдокод без языка** — сложнее показать overflow и IEEE 754 интерактивно. Митигация: пошаговые расчёты с конкретными числами, побитовые таблицы, ASCII-диаграммы памяти.
