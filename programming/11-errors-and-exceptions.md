# Ошибки и исключения

**Предпосылки:** [Функции](05-functions.md) (вызовы функций), [Память](07-memory.md) (стек вызовов, кадры).

<- [Функциональное программирование](10-fp.md) | [Компиляция и интерпретация](12-compilation-and-interpretation.md) ->

Программа читает файл с зарплатами. Файл удалён. Что делать дальше? Если код не умеет обрабатывать такие ситуации, программа просто завершится с ошибкой. Если умеет — покажет понятное сообщение, сохранит контекст или попробует другой путь.

Ошибки неизбежны: файл может отсутствовать, пользователь может ввести текст вместо числа, сеть может оборваться. Вопрос не в том, будут ли ошибки, а в том, как язык предлагает с ними работать.

## Коды ошибок

Самый простой подход — вернуть специальное значение, которое означает неуспех. Здесь и ниже примеры на C. Для понимания важна идея, а не синтаксис C — нужные детали поясняются рядом.

`fopen` открывает файл и возвращает `NULL` (специальное «пустое» значение), если открыть не удалось:

```c
FILE *f = fopen("salaries.txt", "r");

if (f == NULL) {
    printf("Файл не найден\n");
    return 1;
}
```

Программист обязан проверить это значение перед следующим шагом.

Проблема появляется, когда таких вызовов много:

```c
FILE *f = fopen("salaries.txt", "r");
int salary;
fscanf(f, "%d", &salary);    // если f == NULL, программа упадёт
```

Проверку легко забыть. Ошибка не исчезает, она просто переносится в другое место программы.

## Исключения

Другой подход — не возвращать код ошибки, а прерывать обычный ход выполнения и передавать управление обработчику. В Ruby для этого есть конструкция `begin`/`rescue`/`end`: код между `begin` и `rescue` — «попробуй выполнить», код между `rescue` и `end` — «что делать, если произошла ошибка». `=> error` сохраняет объект ошибки в переменную `error`, у которой можно спросить `.message`:

```ruby
begin
  file = File.open("salaries.txt")
  data = file.read
  file.close
rescue => error
  puts "Ошибка: " + error.message
end
```

Если `File.open` не удаётся, управление сразу переходит в `rescue`. Строки ниже места ошибки не выполняются.

Главное отличие от кодов ошибок: пропустить исключение молча нельзя. Если его никто не обработает, программа завершится с сообщением и стеком вызовов.

## Раскрутка стека

Когда исключение брошено, оно поднимается по цепочке вызовов — тем самым кадрам стека из [заметки о памяти](07-memory.md):

```text
to_integer  -> ошибка
parse_line  -> обработчика нет, исключение идёт выше
read_salary -> обработчик есть, исключение ловится здесь
```

Этот процесс называется раскруткой стека (stack unwinding): кадры снимаются в обратном порядке, пока не найдётся обработчик.

```ruby
def to_integer(text)
  Integer(text)  # превращает строку в число; бросает исключение, если строка не число
end

def parse_line(line)
  to_integer(line)
end

def read_salary(filename)
  begin
    file = File.open(filename)
    line = file.gets
    salary = parse_line(line)
    puts "Зарплата: " + salary.to_s
  rescue => error
    puts "Не удалось прочитать: " + error.message
  end
end
```

`rescue` в `read_salary` ловит исключения, которые произошли глубже по цепочке вызовов.

## `Result`: третий путь

Коды ошибок можно забыть проверить. Исключения нельзя забыть, но по сигнатуре функции не видно, какие ошибки она поднимает.

Rust часто использует третий путь — тип `Result` (буквально «результат»): контейнер, который хранит либо успех (`Ok`), либо ошибку (`Err`). Следующий пример на Rust — важна идея, не синтаксис. `match` здесь — конструкция, которая заставляет разобрать оба случая:

```rust
fn read_file(path: &str) -> Result<String, String> {
    // Ok(данные) или Err(сообщение)
}

fn main() {
    match read_file("salaries.txt") {
        Ok(data) => println!("Данные: {}", data),
        Err(error) => println!("Ошибка: {}", error),
    }
}
```

Код, который получает `Result`, обязан явно разобрать оба случая — компилятор не даст забыть ветку с ошибкой.

## Три подхода рядом

| Подход | Где часто встречается | Идея | Цена |
|--------|------------------------|------|------|
| Код ошибки | C | Проверяй вручную после вызова | Легко забыть проверку |
| Исключение | Ruby, Java, Python | Передай ошибку вверх до обработчика | Не всегда видно по сигнатуре функции |
| `Result` | Rust | Явно обработай успех и ошибку | Больше кода в точке вызова |

Каждый подход снимает одну проблему и оставляет другую. Код ошибки даёт прямой контроль, исключения сокращают количество ручных проверок, `Result` делает ошибочный путь явной частью типа.

Следующий вопрос уже не про сбой во время работы, а про запуск программы вообще: почему `ruby file.rb` и `gcc file.c` выглядят так по-разному?
