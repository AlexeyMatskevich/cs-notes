# String

**Предпосылки:** [Что такое Redis](../architecture/00-what-is-redis.md), [event loop](../architecture/01-event-loop.md).

## SDS — Simple Dynamic String

STRING — базовый тип данных Redis, на котором построены счётчики, кеши, блокировки и флаги. Внутри Redis строки хранятся не как C-строки (null-terminated `char*`), а как SDS (`src/sds.h`, реализация динамических строк Redis) — структура, которая хранит длину строки и количество свободного места в буфере. Это даёт O(1) на получение длины (вместо O(n) для `strlen`) и позволяет хранить бинарные данные, включая нулевые байты. SDS автоматически расширяет буфер при append-операциях, удваивая его при маленьких размерах и добавляя по 1 МБ при больших (свыше 1 МБ).

## Три внутренние кодировки

SDS — формат хранения строки, но Redis дополнительно оптимизирует представление в зависимости от содержимого. Redis выбирает кодировку значения автоматически, исходя из содержимого и размера.

**int** — если значение можно представить как 64-битное целое число. Redis хранит число прямо в поле `ptr` объекта `redisObject`, без выделения дополнительной памяти. Команды `INCR`, `INCRBY`, `DECRBY` работают с этой кодировкой арифметически, не конвертируя в строку и обратно.

**embstr** — для коротких строк. В типичных 64-bit сборках Redis порог порядка 44 байт (зависит от версии и сборки). `redisObject` — обёртка, в которую Redis заворачивает каждое значение (тип, кодировка, метаданные; подробно — в [заметке о кодировках](../memory/00-encodings.md)), в типичной 64-bit сборке занимает ~16 байт. `redisObject` и SDS размещаются в одном непрерывном блоке памяти одним вызовом `malloc`. Это экономит один вызов аллокатора и улучшает cache locality. Кодировка read-only: любая модификация (даже `APPEND`) конвертирует значение в raw.

**raw** — для строк длиннее 44 байт. `redisObject` и SDS аллоцируются отдельно — два вызова `malloc`, два блока памяти. Максимальный размер значения — 512 МБ.

Проверить кодировку можно командой `OBJECT ENCODING key`.

## Базовые операции

Кодировки выбираются автоматически — клиент работает с единым набором команд независимо от внутреннего представления.

```redis-cli
SET user:123:name "John"          -- записать строку
GET user:123:name                 -- прочитать → "John"

SET session:abc "data" EX 3600    -- записать с TTL 1 час
TTL session:abc                   -- сколько секунд осталось

SET counter 0
INCR counter                      -- → 1 (атомарно: +1 и вернуть)
INCRBY counter 10                 -- → 11
DECR counter                      -- → 10

SETNX lock:order:42 "owner-1"    -- SET if Not eXists → 1 (захвачено) или 0
SET lock:order:42 "owner-1" NX EX 30  -- NX + TTL за одну команду
```

`INCR` возвращает новое значение. Это одна атомарная операция — увеличить и вернуть результат. В однопоточном event loop никакая другая команда не может вклиниться между чтением и записью.

## TTL: два механизма удаления

Многие применения STRING (кеш, сессии, блокировки) зависят от автоматического удаления ключей по времени. Когда для ключа установлен TTL, Redis удаляет его двумя способами. Lazy expiration: при любом обращении к ключу Redis проверяет, не истёк ли TTL, и если истёк — удаляет ключ и возвращает nil. Active expiration: 10 раз в секунду Redis выбирает случайные ключи из множества ключей с TTL и удаляет истёкшие. Если более 25% проверенных ключей оказались истёкшими, цикл повторяется немедленно. Гарантия: после истечения TTL ключ никогда не вернётся при `GET`.

## Практические применения

Базовые операции и TTL формируют набор готовых паттернов. STRING — самая простая и самая используемая структура. Кеш с TTL (`SET ... EX`), атомарные счётчики (`INCR`), флаги и семафоры (`SET ... NX EX`) — все эти паттерны опираются на одну структуру данных. Паттерны rate limiting и distributed lock, построенные на STRING, подробно рассмотрены в разделе [паттернов](../patterns/01-rate-limiting.md).

Когда нужно хранить несколько связанных полей одного объекта, STRING становится неэффективным: каждый ключ несёт ~70 байт overhead (`redisObject` + запись в глобальной хеш-таблице + expires). Для объектов с полями лучше подходит [Hash](01-hash.md).
