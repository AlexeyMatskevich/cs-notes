# Set

**Предпосылки:** [String](00-string.md), [хеш-таблица](../../../algorithms-and-data-structures/linear/05-hash-table.md), множество (математическое).

SET — неупорядоченная коллекция уникальных строк. Основное преимущество перед LIST — проверка наличия элемента за O(1) и встроенные операции над множествами (пересечение, объединение, разность). SET применяется для хранения тегов, ролей, списков уникальных ID — везде, где важна уникальность и быстрая проверка принадлежности.

## Две внутренние кодировки

**intset** (`src/intset.c`) — отсортированный массив целых чисел. Используется, когда все элементы множества — целые числа и их количество не превышает `set-max-intset-entries` (по умолчанию 512). Intset хранит числа в compact-формате: 16, 32 или 64 бита на элемент, выбирая минимальный размер, достаточный для максимального элемента. Поиск — бинарный (O(log n)), вставка — O(n) из-за сдвига массива, но при малом количестве элементов это быстрее хеш-таблицы из-за отсутствия overhead и cache locality.

**hashtable** (`src/dict.c`) — стандартная хеш-таблица, где значения — NULL (ключи хеш-таблицы и есть элементы множества). Используется, когда хотя бы один элемент — не целое число или количество элементов превысило порог. O(1) на добавление, проверку и удаление.

## Основные команды

Обе кодировки прозрачны для клиента — команды работают одинаково.

```redis-cli
SADD user:123:tags "ruby" "rails" "api"    -- добавить элементы
SADD user:123:tags "ruby"                  -- дубликат игнорируется → 0
SISMEMBER user:123:tags "ruby"             -- есть ли элемент? → 1
SMEMBERS user:123:tags                     -- все элементы (порядок не определён)
SCARD user:123:tags                        -- количество элементов → 3
SREM user:123:tags "api"                   -- удалить элемент
SRANDMEMBER user:123:tags 2               -- 2 случайных элемента (без удаления)
SPOP user:123:tags                         -- случайный элемент с удалением
```

`SISMEMBER` — O(1). Это принципиальное отличие от LIST, где проверка наличия — O(n) (полный обход). Для задач вида «есть ли элемент в коллекции?» SET всегда эффективнее LIST.

## Операции над множествами

Помимо проверки принадлежности, SET позволяет вычислять пересечения и объединения между несколькими множествами на стороне сервера. Redis реализует классические теоретико-множественные операции на стороне сервера:

```redis-cli
SADD user:1:interests "ruby" "python" "go"
SADD user:2:interests "python" "java" "go"

SINTER user:1:interests user:2:interests     -- пересечение → {"python", "go"}
SUNION user:1:interests user:2:interests     -- объединение → {"ruby", "python", "go", "java"}
SDIFF user:1:interests user:2:interests      -- разность → {"ruby"}
```

У каждой из этих операций есть вариант `*STORE`, который сохраняет результат в новый ключ: `SINTERSTORE dest user:1:interests user:2:interests`. Это полезно, когда результат нужно переиспользовать или когда множества большие и повторное вычисление дорого.

Сложность `SINTER` — O(N * M), где N — размер наименьшего множества, M — количество множеств. Redis начинает с самого маленького множества и проверяет каждый его элемент в остальных множествах.

## Когда SET, а не LIST

SET подходит, когда нужна уникальность элементов, быстрая проверка наличия и операции пересечения/объединения. LIST подходит, когда важен порядок вставки, доступ по индексу или блокирующее ожидание (`BRPOP`). Если нужна и уникальность, и упорядоченность — подходит [Sorted Set](04-sorted-set.md).
