# List

**Предпосылки:** [String](00-string.md), [связный список](../../../algorithms-and-data-structures/linear/03-linked-list.md).

## Что хранит LIST

LIST — упорядоченная последовательность строковых элементов. Основные применения — очереди задач (Sidekiq хранит задачи в LIST), ограниченные списки (лента активности, последние N событий) и стеки. Вставка и извлечение с обоих концов — O(1).

## Основные команды

```redis-cli
LPUSH queue:emails "job3"           -- вставить в начало (левый конец)
RPUSH queue:emails "job4"           -- вставить в конец (правый конец)

LPOP queue:emails                   -- забрать из начала
RPOP queue:emails                   -- забрать из конца

BRPOP queue:emails 5                -- блокирующий pop: ждать до 5 секунд
                                    -- если список пуст, соединение блокируется
                                    -- пока не появится элемент или не истечёт таймаут

LRANGE queue:emails 0 -1            -- все элементы (без удаления)
LRANGE queue:emails 0 9             -- первые 10
LLEN queue:emails                   -- длина списка

LTRIM queue:emails 0 99             -- оставить только первые 100 элементов
```

## BRPOP: ожидание без polling

`RPOP` возвращает nil, если список пуст, и клиенту приходится повторять запрос в цикле — это расходует CPU и сеть впустую. `BRPOP` решает проблему: клиент вызывает `BRPOP queue 0` (таймаут 0 — ждать бесконечно), Redis регистрирует его в списке ожидающих. Когда другой клиент выполняет `LPUSH queue item`, Redis находит первого ожидающего и отдаёт ему элемент. Клиент не тратит CPU на polling, Redis не тратит ресурсы на пустые ответы.

`BRPOP` принимает несколько ключей: `BRPOP q1 q2 q3 0` — клиент ждёт элемент в любой из трёх очередей, получает первый появившийся.

## Паттерн: Capped List

Без ограничения размера список растёт бесконечно. `LPUSH` + `LTRIM` поддерживают фиксированный размер, храня только последние N записей (активность пользователя, логи, лента):

```redis-cli
LPUSH user:123:activity '{"action":"login","at":"2025-01-15T10:00:00Z"}'
LTRIM user:123:activity 0 99       -- оставить только последние 100
```

Две команды, но на практике выполняются за микросекунды. Для строгой атомарности можно обернуть в [MULTI/EXEC](../atomicity/01-multi-exec.md) или [pipeline](../architecture/02-pipelining.md).

## Сложность операций

`LPUSH`, `RPUSH`, `LPOP`, `RPOP` — O(1). `LINDEX n` и `LINSERT` — O(n), потому что LIST требует последовательного обхода узлов до нужной позиции. `LRANGE start stop` — O(stop - start + S), где S — количество пройденных элементов до начала диапазона. Для случайного доступа по индексу LIST не подходит — лучше использовать [Sorted Set](04-sorted-set.md) с числовым score.

Если нужны уникальные элементы, а не упорядоченная последовательность, подходящая структура — [Set](03-set.md).

## Внутреннее устройство: quicklist

Внутри Redis LIST реализован как quicklist (`src/quicklist.c`) — двусвязный список, где каждый узел содержит не один элемент, а компактный блок элементов (listpack). Это компромисс: listpack внутри узла экономит память (элементы хранятся рядом, без указателей на каждый), а связный список узлов даёт O(1) вставку в начало и конец. Размер блока в каждом узле контролируется параметром `list-max-listpack-size` (по умолчанию -2, что означает до 8 КБ на узел).

Quicklist также поддерживает сжатие внутренних узлов (`list-compress-depth`). Голова и хвост списка остаются несжатыми (к ним обращаются чаще всего), а средние узлы сжимаются для экономии памяти.
