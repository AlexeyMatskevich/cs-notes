# Атомарность одной команды

**Предпосылки:** [Event loop](../architecture/01-event-loop.md).

## Почему одна команда всегда атомарна

Redis выполняет все команды в одном потоке, последовательно. Между началом и концом выполнения одной команды никакая другая команда не может вклиниться. Это фундаментальное следствие однопоточной модели: нет параллелизма — нет гонок.

`INCR counter` — это не «прочитать, увеличить, записать» как три отдельных шага. Это одна атомарная операция внутри event loop. Даже если тысяча клиентов одновременно отправили `INCR counter`, Redis выполнит их строго по очереди: каждый `INCR` увидит результат предыдущего.

То же относится к `LPUSH` (добавление в список), `SADD` (добавление в множество), `HSET` (установка поля хеша) и любой другой команде. Атомарность одной команды — бесплатная гарантия, не требующая транзакций или блокировок.

## Составные команды с встроенной атомарностью

Многие практические задачи требуют нескольких логических шагов (проверить и записать, прочитать и удалить). Redis объединяет частые комбинации в составные команды. Некоторые команды выполняют несколько логических действий за одну атомарную операцию:

`SET key value NX EX 30` — установить значение только если ключ не существует, с TTL 30 секунд. Проверка, запись и установка TTL — одна атомарная операция. Это основа [распределённых блокировок](../patterns/02-distributed-locks.md).

`GETSET key value` — прочитать старое значение и атомарно установить новое. В Redis 6.2+ появились более узкие варианты: `GETDEL key` (прочитать и удалить) и `GETEX key EX 100` (прочитать и обновить TTL).

`RPOPLPUSH source destination` — атомарно забрать элемент из одного списка и добавить в другой. В Redis 6.2+ появился более общий `LMOVE source destination LEFT RIGHT` и его блокирующий вариант `BLMOVE`. Используется для построения [надёжных очередей](../patterns/03-queues.md).

`INCR`, `INCRBY`, `INCRBYFLOAT`, `HINCRBY`, `HINCRBYFLOAT` — чтение, изменение и запись за одну операцию. Возвращают новое значение.

## Когда одной команды недостаточно

Атомарность одной команды не помогает, когда нужно выполнить несколько команд как единое целое. «Прочитать значение A, на его основе вычислить B, записать B» — между чтением и записью другой клиент может изменить A. Для таких случаев Redis предоставляет [MULTI/EXEC](01-multi-exec.md) и [Lua-скрипты](02-lua-scripting.md).
