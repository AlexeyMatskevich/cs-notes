# Реляционная модель

Интернет-магазин хранит данные о сотрудниках, отделах, заказах и клиентах. Эти данные нужно сохранять надёжно, искать быстро и связывать между собой. Реляционная модель — способ организации данных, предложенный Эдгаром Коддом в 1970 году: данные хранятся в таблицах с жёсткой структурой, а вопросы к ним задаются на специальном языке — SQL.

PostgreSQL — конкретная СУБД (система управления базами данных), реализующая эту модель. Разница между SQL и PostgreSQL — как между спецификацией языка C и компилятором gcc.

## Таблица, строка, столбец

Таблица `employees` описывает сотрудников:

```
 id | name   | dept        | salary | hire_date
----+--------+-------------+--------+------------
  1 | Анна   | engineering |  90000 | 2021-03-15
  2 | Борис  | sales       |  60000 | 2020-07-01
  3 | Вера   | engineering |  85000 | 2022-01-10
  4 | Глеб   | sales       |  70000 | 2019-11-20
  5 | Дина   | engineering |  NULL  | 2023-06-01
```

**Столбец (column)** — свойство, которое описывается: `id`, `name`, `dept`, `salary`, `hire_date`. У каждого столбца есть фиксированный тип данных. Столбец `salary` хранит целые числа — записать туда текст «девяносто тысяч» нельзя. Это аналог поля структуры с фиксированным типом.

**Строка (row)** — один конкретный факт, одна запись. Строка `(1, 'Анна', 'engineering', 90000, '2021-03-15')` описывает одного сотрудника. Аналог одного экземпляра структуры.

**Таблица (table)** — коллекция строк с одинаковой структурой (одинаковым набором столбцов). Аналог массива структур одного типа.

## Отсутствие порядка строк

В массиве элементы упорядочены: у каждого есть индекс 0, 1, 2. В реляционной таблице **порядка строк не существует**. Таблица — это множество (точнее, мультимножество, допускающее дубликаты), а не последовательность. PostgreSQL хранит строки в произвольном физическом порядке, и то, что «Анна» отображается первой — случайность, а не гарантия.

Следствие: если нужен порядок в результате (например, «сотрудники от старшего к младшему»), его нужно **явно запросить** через ORDER BY.

## Мультимножество

Термин «мультимножество» (multiset, bag) означает коллекцию, допускающую дубликаты — в отличие от множества (set), где каждый элемент уникален. SQL-запрос `SELECT dept FROM employees` вернёт пять строк, включая повторяющиеся значения `engineering`. Дубликаты не удаляются автоматически — для этого нужен отдельный инструмент (DISTINCT).

## Декларативность SQL

SQL — **декларативный** язык. Запрос описывает *что* нужно получить, а не *как* вычислить. Запрос `SELECT name FROM employees WHERE salary > 80000` — вопрос «имена сотрудников с зарплатой выше 80000». СУБД сама решает, как найти ответ: сканировать всю таблицу, использовать индекс или прочитать данные из кеша.

## Данные для примеров

Все файлы в этом курсе используют один набор таблиц — интернет-магазин. Определения таблиц (CREATE TABLE) и заполнение данными (INSERT) подробно разбираются в [DDL](../schema/00-tables-and-types.md). Здесь — минимальный набор для запуска примеров:

```sql
CREATE TABLE departments (
    id        integer,
    name      text,
    budget    integer
);

INSERT INTO departments VALUES
(1, 'engineering', 500000),
(2, 'sales',       300000),
(3, 'hr',          150000);

CREATE TABLE employees (
    id            integer,
    name          text,
    department_id integer,
    salary        integer,
    hire_date     date
);

INSERT INTO employees VALUES
(1, 'Анна',    1, 90000,  '2021-03-15'),
(2, 'Борис',   2, 60000,  '2020-07-01'),
(3, 'Вера',    1, 85000,  '2022-01-10'),
(4, 'Глеб',    2, 70000,  '2019-11-20'),
(5, 'Дина',    1, NULL,   '2023-06-01'),
(6, 'Евгений', NULL, 55000, '2024-02-01');

CREATE TABLE customers (
    id    integer,
    name  text,
    email text,
    city  text
);

INSERT INTO customers VALUES
(1, 'Alice',   'alice@example.com',   'New York'),
(2, 'Bob',     'bob@example.com',     'London'),
(3, 'Charlie', 'charlie@example.com', 'Tokyo');

CREATE TABLE orders (
    id          integer,
    customer_id integer,
    employee_id integer,
    total       integer,
    created_at  date
);

INSERT INTO orders VALUES
(1, 1, 1, 15000, '2024-01-15'),
(2, 2, 2, 8000,  '2024-02-20'),
(3, 1, 3, 22000, '2024-03-10'),
(4, 3, 1, 5000,  '2024-03-25'),
(5, 2, 4, 12000, '2024-04-05');
```

Таблица `employees` — основная для примеров в querying/. `departments` появляется при изучении JOIN. `orders` и `customers` — для сложных многотабличных запросов.
