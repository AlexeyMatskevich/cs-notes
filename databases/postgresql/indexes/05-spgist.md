# SP-GiST — индекс для разбиения пространства (trie/quad-tree и др.)

**Предпосылки:** [B-tree](00-btree.md) (что даёт порядок и зачем он нужен), [GiST](02-gist.md) (деревья поиска для «нелинейных» данных), базовая идея [дерева](../../algorithms-and-data-structures/non-linear/01-tree.md).

Чаще всего встречаются два сценария: «есть порядок → B-tree» и «нет порядка → GiST/GIN». SP-GiST нужен для третьего случая: когда значения естественно разбиваются по пространству или по префиксам, и поиск выгодно строить как навигацию по разбиениям (trie, radix tree, quad-tree, k-d tree и т.п.).

SP-GiST расшифровывается как **Space-Partitioned Generalized Search Tree** — обобщённый индекс, который хранит данные в дереве разбиений. В отличие от GiST, где внутренние узлы часто содержат охватывающие регионы (bounding boxes) и возможны recheck, SP‑GiST строит дерево, в котором каждый шаг уменьшает область поиска через разбиение пространства.

## Когда SP-GiST имеет смысл

SP‑GiST полезен, когда:

- данные имеют естественную «иерархию по префиксам» (строки, пути, домены),
- или данные живут в многомерном пространстве и хорошо режутся на регионы,
- и запросы похожи на «в какой ветке это лежит?» (prefix/range по части ключа/поиск по региону).

Если вам нужен `ORDER BY` и диапазоны по тотальному порядку, почти всегда проще и надёжнее B-tree. SP‑GiST не про порядок, а про разбиения.

## Интуиция: trie для префиксов

Представим индекс по строкам как trie:

```text
root
 ├─ a
 │   ├─ l
 │   │   └─ i  ...  ("alice")
 │   └─ n  ...       ("anna")
 └─ b
     └─ o  ...       ("bob")
```

Запрос `LIKE 'al%'` в таком дереве означает: «спуститься по `a → l` и взять всё поддерево». Это другой способ ускорения, чем B-tree, где всё держится на сортировке и диапазонном скане.

## Интуиция: разбиение 2D пространства

Для точек на плоскости дерево может делить пространство на квадранты (quad-tree). Запрос «внутри прямоугольника» превращается в обход только тех регионов, которые пересекаются с прямоугольником.

В этом смысле SP‑GiST — индекс, который выигрывает, когда разбиение быстро отсеивает большую часть данных.

## Что важно проверить

1. **Operator class решает всё.** SP‑GiST — это фреймворк. Конкретная логика разбиения и поиска определяется operator class для типа данных.
2. **Это не замена B-tree.** Если нужен порядок (сортировки, range scan), B-tree обычно проще и предсказуемее.
3. **Это не GiST.** GiST хранит охватывающие регионы и часто требует recheck. SP‑GiST идёт через разбиение пространства и «навигацию» по дереву.

## Практическая карта выбора

- Нужны `=`, диапазоны, сортировка, prefix‑LIKE → начните с [B-tree](00-btree.md).
- Нужны «пересечения/внутри/ближайший» для диапазонов/геометрии → [GiST](02-gist.md).
- Нужны «содержит элемент» для массивов/JSONB/полнотекста → [GIN](01-gin.md).
- Нужна структура разбиений (trie/пространство) и есть подходящий operator class → SP‑GiST.
