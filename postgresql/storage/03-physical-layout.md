# Физическая структура хранения — справочник

**Предпосылки:** [страницы и кортежи](01-pages-and-tuples.md), [WAL](../durability/00-wal.md), [VACUUM](../maintenance/00-vacuum.md).

Это справочный раздел. Здесь собрана информация о файловой организации PostgreSQL — полезно для диагностики и понимания, где физически находятся данные.

### Иерархия: кластер → база → объекты

**Кластер (Cluster)** — вся инсталляция PostgreSQL, управляемая одним сервером. Не путать с «кластером серверов» — здесь термин исторический, означает «группу баз данных».

```text
PostgreSQL Cluster (data directory, например /var/lib/postgresql/data)
│
├── base/                          ← все пользовательские базы данных
│   ├── 1/                         ← template1 (OID = 1)
│   ├── 16384/                     ← база данных myapp (OID = 16384)
│   │   ├── 16385                  ← таблица users (main fork)
│   │   ├── 16385_fsm              ← FSM для users
│   │   ├── 16385_vm               ← VM для users
│   │   ├── 16390                  ← таблица orders
│   │   ├── 16395                  ← индекс users_pkey
│   │   └── ...
│   └── 16500/                     ← другая база данных
│
├── global/                        ← общие для кластера таблицы (pg_database, pg_authid)
│
├── pg_wal/                        ← WAL-файлы
│   ├── 000000010000000000000001
│   └── ...
│
├── pg_xact/                       ← CLOG (статусы транзакций)
│
└── postgresql.conf, pg_hba.conf   ← конфигурация
```

**OID (Object Identifier)** — уникальный числовой идентификатор объекта. Имена файлов в base/ — это OID объектов.

### Форки (forks) — файлы одного объекта

Каждый объект (таблица, индекс) состоит из нескольких файлов — форков.

```text
Таблица users (relfilenode = 16385):

16385           ← main fork (данные — tuples)
16385_fsm       ← FSM fork (Free Space Map)
16385_vm        ← VM fork (Visibility Map)
```

| Fork | Назначение |
|------|------------|
| main | Данные (tuples для таблиц, записи для индексов) |
| fsm | Карта свободного места для INSERT |
| vm | Карта видимости для VACUUM и index-only scan |

### Сегменты — для больших таблиц

Один файл ограничен 1 GB. Большие таблицы разбиваются на сегменты:

```text
16390           ← первый сегмент (страницы 0 - 131071)
16390.1         ← второй сегмент
16390.2         ← третий сегмент
...
```

### Как найти файл таблицы

```sql
-- pg_class — системный каталог с метаданными объектов
SELECT oid, relname, relfilenode
FROM pg_class
WHERE relname = 'users';

 oid   | relname | relfilenode
-------+---------+-------------
 16385 | users   | 16385
```

`relfilenode` — имя файла. Обычно совпадает с OID, но может измениться после VACUUM FULL, TRUNCATE, или REINDEX.

### Связь компонентов — диаграмма

```text
┌─────────────────────────────────────────────────────────────────┐
│                    Файл таблицы (main fork)                     │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐           │
│  │ Page 0   │ │ Page 1   │ │ Page 2   │ │ Page 3   │ ...       │
│  │ tuples   │ │ tuples   │ │ tuples   │ │ tuples   │           │
│  │ctid=(0,*)│ │ctid=(1,*)│ │ctid=(2,*)│ │ctid=(3,*)│           │
│  └──────────┘ └──────────┘ └──────────┘ └──────────┘           │
└─────────────────────────────────────────────────────────────────┘
        ↓              ↓              ↓              ↓
┌─────────────────────────────────────────────────────────────────┐
│                         FSM fork                                │
│  Page 0: ~500 байт │ Page 1: 0 │ Page 2: ~4000 │ Page 3: ~200  │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│                         VM fork                                 │
│  Page 0: 1 (all-visible) │ Page 1: 0 │ Page 2: 1 │ Page 3: 0   │
└─────────────────────────────────────────────────────────────────┘


┌─────────────────────────────────────────────────────────────────┐
│                Файл индекса (отдельный файл!)                   │
│  B-tree страницы с записями: (ключ) → (ctid)                    │
│  Например: 'Alice' → (2, 5) = страница 2, позиция 5             │
└─────────────────────────────────────────────────────────────────┘
```

**Важно:** Индексы — отдельные файлы со своими страницами и своей FSM. Не внутри файла таблицы.
