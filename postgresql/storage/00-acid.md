# ACID — фундаментальный контракт СУБД

**Предпосылки:** SQL, BEGIN/COMMIT/ROLLBACK.

PostgreSQL начинается с контракта: какие гарантии получает приложение, и за что СУБД платит ресурсами и сложностью.

### Две фундаментальные боли

Любая база данных существует, чтобы решить две проблемы, которые невозможно решить простым файлом.

**Боль 1: Сбой посередине операции.** Перевод денег требует двух действий: списать с одного счёта, зачислить на другой. Если программа упала между ними — деньги исчезли. Файл не даёт никаких гарантий: запись может оборваться на полуслове.

**Боль 2: Параллельный доступ.** Два пользователя одновременно списывают деньги с одного счёта. Оба читают баланс 200, оба вычисляют «200 - 100 = 100», оба записывают 100. Должно остаться 0, осталось 100. Файл не координирует читателей и писателей.

Транзакция — это контракт СУБД: «я гарантирую, что твои операции либо выполнятся целиком, либо не выполнятся вообще, и параллельные пользователи не сломают твои данные».

### ACID — четыре гарантии контракта

**Atomicity (атомарность):** Транзакция неделима. При сбое посередине все изменения откатываются, как будто транзакции не было.

**Consistency (согласованность):** База переходит из одного валидного состояния в другое. СУБД проверяет свои ограничения (NOT NULL, UNIQUE, FOREIGN KEY). Бизнес-инварианты — ответственность программиста.

**Isolation (изоляция):** Параллельные транзакции не видят промежуточных состояний друг друга. Результат как будто они выполнялись по очереди.

**Durability (надёжность):** После COMMIT данные не потеряются. Даже если через секунду отключится питание.

Каждая буква — это боль, которую СУБД берёт на себя. Но за каждую гарантию приходится платить. Вся архитектура PostgreSQL — это история компромиссов: как дать максимум гарантий за минимальную цену.

Цена гарантий начинается с физического хранения — [страницы и кортежи](01-pages-and-tuples.md) решают проблему управляемого обновления данных на диске.
