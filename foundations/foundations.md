# Основы представления данных

**Предпосылки:** нет.

В памяти компьютера — только элементы с двумя состояниями. Из этого ограничения приходится собирать всё остальное: числа, дробные величины, текст, составные сообщения между машинами. Каждый шаг — это компромисс: что именно платится за то, чтобы группа битов начала означать «число −3», «буква Щ» или «32-битное слово, пришедшее по сети».

После серии читатель понимает, почему `INT` ограничен ±2 миллиардами, почему `0.1 + 0.2 ≠ 0.3`, почему UTF-8 устроен именно так, почему `htons()` нужен для сетевого порта, и где каждое из этих решений сломается, если про него забыть.

2. [Целые числа](integers.md) — беззнаковые, знаковые, дополнительный код, переполнение.
3. [Побитовые операции](bitwise-operations.md) — AND, OR, XOR, NOT, сдвиги, маски, флаги.
4. [Числа с плавающей точкой](floating-point.md) — IEEE 754, нормализация, почему `0.1 + 0.2 ≠ 0.3`.
5. [IEEE 754: крайние случаи](floating-point-edge-cases.md) — округление, NaN/Inf, денормализованные, катастрофическая потеря точности, практические рекомендации.
6. [Кодирование текста](text-encoding.md) — код Бодо, ASCII, кодовые страницы, Unicode, UTF-8.
7. [Нормализация Unicode и графемные кластеры](unicode-normalization-and-graphemes.md) — символ ≠ code point ≠ байт, NFC/NFD, emoji ZWJ, сравнение строк.
8. [Порядок байтов](endianness.md) — little-endian, big-endian, сетевой порядок.

### Связи между заметками

```text
binary ─> integers ─> bitwise ─> floating ─> edge-cases
   │                                              │
   └─────────────────────> text ─> normalization ─> endianness
```

Текст опирается только на `binary`, поэтому `text-encoding` можно читать сразу после первой заметки, если интерес ведёт туда раньше. Остальная цепь держится на числах и операциях над ними.

## Как всё связано

Каждая заметка решает один конкретный компромисс и оставляет другой.

- **Байт.** Группа из 8 бит выбрана не математически, а индустриально: в архитектуре IBM System/360 (1964) 8-битная единица предложена как опция, поддерживающая одновременно 8-битное представление 7-битного ASCII и расширенный BCD-код для обмена; после System/360 восьмёрка закрепилась как индустриальный стандарт. Плата — адресуемость меньшей единицы (7-битного символа) потеряна на уровне архитектуры.
- **Дополнительный код.** Единственный рабочий способ, при котором сложение знаковых и беззнаковых чисел делается одной схемой. Плата — асимметричный диапазон (`i8` покрывает `−128..127`, не `−127..127`) и тихое переполнение, если разработчик не проверяет.
- **IEEE 754.** Плавающая точка жертвует точной арифметикой десятичных дробей ради широкого диапазона с фиксированной шириной слова. `0.1` нельзя точно записать в двоичной системе — не баг, а следствие выбора основания.
- **UTF-8.** Ради обратной совместимости с ASCII кодировка принимает переменную длину символа, что превращает операции «взять N-й символ» и «длина строки» из одной инструкции в полноценный разбор.
- **Графемный кластер.** Пользователь видит «одну букву», но она может быть составлена из нескольких code points (`é` как `e + ́`, `👨‍👩‍👧` как пять code points через ZWJ). Это разрыв между слоем Unicode и слоем отображения.
- **Сетевой порядок байтов.** Когда два слоя (CPU и протокол) договариваются по-разному, значение больше байта читается искажённым. `htons(80)` в TCP-заголовке — напоминание об этой невидимой границе.
