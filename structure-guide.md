# Структура папок и файлов

Инструкция для агентов: как организовать новую тематическую папку в этом репозитории. Извлечена из существующих `algorithms-and-data-structures/` и `databases/`.

Для стиля написания текста см. [styleguide.md](styleguide.md).

---

## Иерархия директорий

Максимум 4 уровня вложенности:

```
тематическая-папка/          # уровень 1: домен (databases, ruby, rails)
├── index.md                 # мастер-индекс (обязателен)
├── shared-concept.md        # общая теория, если нужна нескольким подпапкам
├── подкатегория/            # уровень 2: логическая группа (storage, concurrency)
│   ├── 00-first-topic.md    # уровень 3: файлы заметок
│   ├── 01-second-topic.md
│   └── 02-third-topic.md
└── practice/                # опционально: прикладные сценарии
    └── scenario-name.md
```

Для технологий внутри домена добавляется ещё один уровень:

```
databases/
├── distribution.md              # shared: общая теория распределения
├── postgresql/
│   ├── index.md
│   ├── storage/
│   │   ├── 00-acid.md
│   │   └── 01-pages-and-tuples.md
│   └── concurrency/
│       ├── 00-mvcc.md
│       └── 01-anomalies.md
└── redis/
    ├── index.md
    └── architecture/
        └── 00-what-is-redis.md
```

### Когда создавать подкатегорию

- 3+ файлов по одной теме → выносить в подпапку.
- 1–2 файла → оставить в родительской директории.
- Файлы внутри подкатегории объединяет общая тема и направление зависимостей (storage → durability → concurrency).

## Именование

### Директории

kebab-case: `query-processing`, `data-structures`, `schema-design`.

### Файлы заметок

`NN-kebab-case.md` — двузначный префикс определяет порядок чтения:

```
00-acid.md
01-pages-and-tuples.md
02-toast.md
```

Номер = порядок зависимостей: файл `02` может ссылаться на `00` и `01`, но не наоборот.

### Специальные файлы

| Файл | Назначение |
|------|-----------|
| `index.md` | Мастер-индекс тематической папки |
| `distribution.md`, `shared-*.md` | Общая теория, используемая несколькими подпапками |

Файлы без числового префикса — либо индексы, либо shared-концепции.

## Шаблон index.md

Каждая тематическая папка (и каждая технология внутри домена) содержит `index.md`:

```markdown
# Заголовок домена/технологии

**Предпосылки:** [концепция 1](path/to/file.md), [концепция 2](path/to/file.md), базовое знание X.

Вводный абзац: зачем эта тема существует, какие задачи решает, какие компромиссы определяют её устройство. Без мета-комментариев вроде "в этом разделе мы рассмотрим".

## Порядок изучения

Заметки сгруппированы по зависимостям: от X к Y и далее к Z.

### Подкатегория 1

Краткое пояснение, почему эти темы идут вместе.

- [Тема A](subcategory/00-topic-a.md) — одно предложение о сути
- [Тема B](subcategory/01-topic-b.md) — одно предложение о сути

### Подкатегория 2

- [Тема C](subcategory2/00-topic-c.md) — одно предложение о сути

## Как всё связано

Серия компромиссов в формате **X vs Y:**

**Durability vs Performance:** Проблема. Решение. Цена решения.

**Isolation vs Performance:** Проблема. Решение. Цена решения.

## Sources

- Автор, год, *Название*. URL
```

### Ключевые свойства index.md

- Ссылки на все файлы внутри папки, сгруппированные по подкатегориям.
- Каждая ссылка сопровождается кратким пояснением (1 предложение).
- Секция «Как всё связано» показывает trade-offs домена.
- Опционально: сводные таблицы для сравнения (как таблица выбора индексов в PostgreSQL).
- Опционально: секция «См. также» со ссылками на связанные разделы в других папках.

## Шаблон файла заметки

```markdown
# Заголовок концепции

**Предпосылки:** [зависимость 1](path.md), [зависимость 2](path.md).

Вводный абзац: какую проблему решает эта концепция или зачем она нужна. Сразу в тему, без "в этой заметке мы...".

## Секция 1: проблема или контекст

Проза, объясняющая проблему. Конкретные эффекты: latency, memory, OOM, CPU.

## Секция 2: решение / механизм

Как устроено решение. Код-якоря: "страница кучи (`struct heap_page`)" — что это, где живёт, зачем нужно.

### Подсекция при необходимости

Детали механизма.

## Секция N: следствия / trade-offs

К чему приводит решение, какие ограничения вносит.

## Sources

- Автор, год, *Название* — контекст: URL
```

### Принципы содержания

Стиль написания текста подробно описан в [styleguide.md](styleguide.md). Здесь — только то, что влияет на структуру файлов:

- **Один файл = одна концепция.** Критерий разделения: концепция имеет собственное определение, собственные зависимости и может быть целью перекрёстной ссылки. Пример: MVCC, аномалии и уровни изоляции — три разных файла, потому что у каждого свои предпосылки и на каждый ссылаются независимо.
- **Предпосылки определяют порядок файлов.** Файл не использует термины, не определённые в нём самом или в файлах из предпосылок. Числовой префикс отражает этот порядок: `02` зависит от `00` и `01`.

## Перекрёстные ссылки

Относительные пути от текущего файла:

```markdown
<!-- внутри подкатегории -->
[предыдущая тема](00-previous.md)

<!-- между подкатегориями одной папки -->
[WAL](../durability/00-wal.md)

<!-- между тематическими папками -->
[LRU-кэш](../../algorithms-and-data-structures/linear/06-lru-cache.md)

<!-- на shared-файл уровнем выше -->
[Распределение данных](../distribution.md)
```

Ссылки ставятся в том месте текста, где концепция впервые упоминается.

## Общие теоретические файлы (shared concepts)

Когда одна концепция используется несколькими технологиями — она выносится на уровень выше:

```
databases/
├── distribution.md          # общая теория: репликация, failover, шардинг
├── postgresql/
│   └── distribution/        # PostgreSQL-специфика ссылается на ../distribution.md
└── redis/
    └── distribution/        # Redis-специфика ссылается на ../distribution.md
```

Shared-файл содержит абстрактные понятия. Конкретные реализации (как PostgreSQL делает репликацию) — в файлах технологии.

## Практические паттерны

Для прикладных сценариев — отдельная подпапка `patterns/` или `practice/`:

```
redis/
└── patterns/
    ├── 00-caching.md
    ├── 01-rate-limiting.md
    └── 02-distributed-locks.md

rails/redis/
└── practice/
    ├── bitmap-dau-retention.md      # без числового префикса —
    ├── hash-checkout-cart.md        # порядок не важен,
    └── sorted-set-call-queue.md     # файлы независимы
```

Если файлы практики зависят друг от друга — нумеровать. Если независимы — kebab-case без префикса, имя описывает «структура-данных + сценарий».

## Чек-лист: создание новой тематической папки

1. Создать директорию в kebab-case в корне или внутри существующего домена.
2. Определить подкатегории (3+ файлов → подпапка).
3. Определить порядок зависимостей внутри каждой подкатегории и пронумеровать файлы `00-`, `01-`, ...
4. Создать `index.md` с предпосылками, порядком изучения, секцией «Как всё связано» и sources.
5. В каждом файле заметки: заголовок, предпосылки со ссылками, нарратив, sources.
6. Проверить: ни один термин не используется до определения (в этом файле или в предпосылках).
7. Проставить перекрёстные ссылки на связанные файлы в других папках.
8. Если есть общая теория для нескольких технологий — вынести в shared-файл уровнем выше.
9. Обновить file map в `CLAUDE.md`.
